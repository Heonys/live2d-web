## メインスレッド追跡

> Workerエントリを含むトラッキングは、モバイルと外部利用者の検証が完了するまで **experimental** です。minor変更にはmigrationを記録し、patchではbreaking changeを行いません。

MediaPipe は任意 peer で、この subpath からだけ読み込まれます。WASM・Face Landmarker model・video frame・schedule はアプリが渡します。tracker は正規化値だけを保持します。

```ts
import { createMediaPipeFaceTracker } from
  'live2d-web/tracking/mediapipe'

const tracker = await createMediaPipeFaceTracker({
  modelAssetPath: '/mediapipe/face_landmarker.task',
  wasmPath: '/mediapipe/wasm',
})
const detach = tracker.attach(character, {
  mapping: 'auto',
  channels: { mouth: false },
})

tracker.update(video, performance.now())

detach()
tracker.dispose()
```

## 任意の Worker

Worker mode は推論を描画スレッドから分離します。update() は非同期で1 frameずつ処理し、busy frame は skipped になります。起動失敗時の暗黙 fallback はありません。初期化の期限は30秒、推論の期限は10秒です。timeout は `tracking-error` で reject し、その tracker を終了するため、アプリは新しい Worker tracker を作成するか main mode に切り替える必要があります。

```ts
const tracker = await createMediaPipeFaceTracker({
  execution: 'worker',
  modelAssetPath: '/mediapipe/face_landmarker.task',
  wasmPath: '/mediapipe/wasm',
  workerFactory: () => new Worker(
    new URL('./face-tracking.worker.ts', import.meta.url),
    { type: 'module' },
  ),
})
```

## 起動段階とモバイルの状態

Playground は、camera 準備、tracker 作成、最初の inference、1秒の calibration、
最終的な tracked 遷移を別々に表示します。同じ区間の MediaPipe JavaScript、
WASM、task の Resource Timing も表示するため、長い cold start をすぐに推論
時間だと判断せず、遅い段階を確認できます。

warm なローカル tracker 作成は、3つの desktop engine で中央値5秒の基準を
十分下回っています。iPhone Safari は実機検証が必要で、Android Chrome は
明示的に未検証です。Worker 作成が失敗または timeout した場合は
`tracking-error` を表示し、利用者が main mode で tracker を作り直せるように
してください。無期限に待ったり暗黙に fallback したりしません。
