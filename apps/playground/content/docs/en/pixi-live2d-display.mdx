## What changes

`pixi-live2d-display` renders a Live2D model as a PixiJS `Container`, so Pixi owns the canvas, the ticker and the WebGL context. This runtime owns them itself. The six `@pixi/*` peer dependencies go away, and nothing here is tied to a Pixi version.

That matters for a specific reason: its peer range is `@pixi/core: "^6"`, and Pixi is on v8. It was last published in December 2023.

```html title="index.html, before"
<!-- Cubism Core has to be in the page before the plugin runs -->
<script src="/live2dcubismcore.min.js"></script>
```

```ts title="Before"
import { Live2DModel } from 'pixi-live2d-display'
import * as PIXI from 'pixi.js'

// the plugin reads window.PIXI.Ticker to update models
window.PIXI = PIXI

const app = new PIXI.Application({ view: canvas })
const model = await Live2DModel.from('/models/avatar.model3.json')
app.stage.addChild(model)
model.scale.set(0.3)
model.position.set(200, 100)
```

```ts title="After"
import { createLive2D } from 'live2d-web'

const character = await createLive2D({
  container: document.querySelector('#stage')!,
  coreUrl: '/live2dcubismcore.min.js',
  src: '/models/avatar.model3.json',
})
```

There is no application, no stage and no ticker to register. `coreUrl` loads Cubism Core, so the page needs no script tag and nothing has to run in the right order. Give the container a CSS size and the canvas fills it.

## Method by method

| pixi-live2d-display | live2d-web |
| --- | --- |
| `Live2DModel.from(url)`, `stage.addChild()` | `createLive2D({ container, coreUrl, src })` |
| `<script src="live2dcubismcore.min.js">` in the page | `coreUrl` |
| another `addChild()` | `addModel()`, or another `<Live2DModel>` |
| `model.motion(group, index, priority)` | `motion(group, index, { priority })` |
| `MotionPriority.NORMAL` / `FORCE` / `IDLE` | `'normal'` / `'force'` / `'idle'` |
| `model.expression(id)` | `expression(id)` |
| `model.focus(x, y)` | `focus(x, y)`, `focusAt(clientX, clientY)` |
| `model.tap(x, y)`, `model.hitTest(x, y)` | `hitTest(clientX, clientY)` |
| `model.x`, `y`, `scale`, `anchor` | `fit` |
| `autoUpdate`, ticker registration | automatic |
| `autoInteract` | `followPointer`, `onTap` |
| `coreModel.setParameterValueById()` | `setParameter(id, value)` |
| `model.destroy()` | `dispose()` |

Placement is the one that is not a rename. Pixi transforms are pixels on a stage you sized; `fit` describes the framing instead, and recomputes it on every resize. Turn on [the placement overlay](/docs/en/debug) to drag a model where you want it and copy the value out.

## What does not come across

- **Cubism 2.1 models.** `pixi-live2d-display` ships a `/cubism2` entry. This runtime is Cubism 4/5 only, and a `.moc` file will not load.
- **The Pixi scene graph.** Filters, blend modes and mixing a model with other sprites all belong to Pixi. This runtime owns its canvas, so a model cannot be placed inside a Pixi scene.
- **Audio playback.** There is no `SoundManager` and no `model.speak(url)`. The application plays the audio it already owns, and [lip sync](/docs/en/lip-sync) drives the mouth from it.

## Cubism Core

This is where a migration usually stops first. The bundled Framework 5-r.5 adapter needs **Cubism Core 5.3**, distributed as `core/06`. An older `core/05` file fails while loading the moc, so the Core script you were serving for Pixi may need replacing. [Core and models](/docs/en/core-and-models) covers where to get it.

## Order to do it in

1. Serve Cubism Core 5.3 and confirm a model renders at all.
2. Replace construction: `createLive2D()` for JavaScript, `<Live2DCanvas>` with `<Live2DModel>` for React.
3. Replace transforms with `fit`, using the placement overlay to find the value.
4. Rename the calls in the table above.
5. Remove `pixi-live2d-display` and every `@pixi/*` dependency Pixi itself does not need.

Run [the inspector](/docs/en/model-inspection) on the model first if it does not render. It reports the moc version and every missing asset, which answers most of what goes wrong on the way over.
