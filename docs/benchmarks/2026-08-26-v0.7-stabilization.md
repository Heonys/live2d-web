# v0.7 안정화 검증 — 2026-08-26

대상은 `develop`의 v0.7 안정화 구현이다. 공개 API 기준선, 접근성, 독립 소비자
설치 경계와 MediaPipe warm tracker 생성 시간을 확인했다. 실제 iPhone Safari
검증은 아직 수행하지 않았으므로 이 문서는 v0.7 출시 완료를 뜻하지 않는다.

## 공개 API와 소비자

- `@microsoft/api-extractor` 보고서로 root, React, inspect, devtools,
  MediaPipe main/Worker와 cubism-webgl의 실제 배포 타입을 고정했다.
- `pnpm api:check`는 보고서와 현재 build의 차이를 실패로 처리한다. 의도한 API
  변경은 보고서와 CHANGELOG를 함께 갱신해야 한다.
- 현재 packed tarball은 React/React DOM `18.2.0`과 `19.2.8`의 Vite
  typecheck·production build를 모두 통과했다.
- 모노레포 밖의 임시 Vite Vanilla에는 npm `0.6.0`, 임시 Next React에는 현재
  packed tarball을 설치했다. 문서의 절차로 Hiyori를 로드하고 Tap 모션 완료와
  `dispose()` 뒤 Canvas 0개·console error 0개를 확인했다. 이 검증은 외부 사용자
  채택이나 외부 프로젝트 수로 집계하지 않는다.

## 접근성과 오류 안내

- Canvas는 기존 기본 동작을 유지하면서 선택적으로 장식 이미지 또는 이름 있는
  이미지 semantics를 받을 수 있다. React에서 값이 같은 inline 설정은 Stage를
  다시 만들지 않는다.
- Landing, 영문 Docs, Playground, Inspector는 Chromium axe smoke에서 자동으로
  검출 가능한 위반 0개를 확인했다. 이 결과는 수동 키보드·스크린 리더 검증을
  대신하지 않는다.
- 세 언어 Troubleshooting은 공개 `Live2DErrorCode` 10개의 원인·확인·수정·재시도
  여부를 모두 포함한다. Playground 오류 화면은 해당 영문 anchor로 연결된다.

## MediaPipe warm 생성

공식 portrait 입력과 실제 Hiyori 동시 렌더 환경에서 main과 Worker를 번갈아
각각 3회 실행한 중앙값이다. 자산은 로컬 origin의 warm HTTP cache에서 읽었다.
단위는 ms다.

| 브라우저 | main tracker 생성 | Worker tracker 생성 | main inference p95 | Worker round-trip p95 |
| --- | ---: | ---: | ---: | ---: |
| Chromium | 338.6 | 373.4 | 13.6 | 24.2 |
| WebKit | 367 | 383 | 18 | 17 |
| Firefox | 270 | 340 | 193 | 213 |

모든 tracker 생성 중앙값은 v0.7 기준인 5초 이내다. 따라서 이번 작업에서는
다운로드 캐시나 WASM/task 생성 경로를 추측으로 변경하지 않았다. Firefox의
느린 추론은 생성 지연이 아니라 기존에 기록된 실행 성능 한계이며, Worker가
렌더 스레드에서 분리한다.

`LIVE2D_TRACKING_SOAK_MINUTES=5 pnpm test:tracking:soak`도 통과했다. 설정한
5분은 main과 Worker의 합산 시간이며 이번 실행은 각각 약 2.5분 동안 추론,
재생성, pending 정착, 최종 dispose와 heap/error 한계를 검사했다.

Playground는 실제 카메라 시작 시 다음 구간을 별도로 표시한다.

1. 카메라 준비
2. tracker 생성
3. 첫 inference
4. 1초 중립 보정
5. `tracked` 전환까지 총 시간

같은 시점의 MediaPipe JS chunk, WASM과 task 파일은 Resource Timing 이름과
duration으로 함께 표시한다. cold 시작이 길면 이 구간으로 네트워크 다운로드와
로컬 초기화를 구분한다. 영상·프레임·얼굴 값은 기록하지 않는다.

## 남은 실기기 검증

iPhone Safari에서 Main과 Worker를 각각 5분 실행하는 검증은 아직 남아 있다.
Main 정상 동작, Worker 정상 동작 또는 명시적 `tracking-error`, 화면 회전,
백그라운드 복귀, 중지·재시작과 카메라/Worker 정리를 실제 기기에서 확인해야
한다. Android Chrome은 공개적으로 미검증인 비차단 항목이다.

재현 명령은 `pnpm api:check`, `pnpm verify:packed-consumers`,
`pnpm benchmark:tracking`이다. 브라우저별 원본 측정은 ignored
`benchmark-results/tracking.<browser>.json`에 생성된다.
